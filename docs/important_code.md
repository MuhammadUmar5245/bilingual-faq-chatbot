## 1. Hybrid retriever — TF-IDF first, SBERT fallback with score fusion

*Source: backend/nlp/hybrid.py — `HybridRetriever.retrieve`*

```python
    def retrieve(self, query: str) -> RetrievalResult:
        start = time.perf_counter()
        with self._lock:
            faqs, tfidf, sbert, clf = self.faqs, self.tfidf, self.sbert, self.classifier
        lang = detect_language(query)
        if not faqs:
            return RetrievalResult(None, 0.0, "fallback", lang, None,
                                   elapsed_ms=(time.perf_counter() - start) * 1000)

        t_scores = tfidf.scores(query)
        t_best = int(t_scores.argmax())
        t_score = float(t_scores[t_best])
        s_score = None

        if t_score >= self.tfidf_threshold:
            faq, conf, method, scores = faqs[t_best], t_score, "tfidf", t_scores
        elif sbert is not None:
            w = self.fusion_weight
            s_scores = (1 - w) * sbert.scores(query) + w * t_scores
            s_best = int(s_scores.argmax())
            s_score = float(s_scores[s_best])
            if s_score >= self.sbert_threshold:
                faq, conf, method, scores = faqs[s_best], s_score, "sbert", s_scores
            else:
                faq, conf, method, scores = None, s_score, "fallback", s_scores
        else:
            faq, conf, method, scores = None, t_score, "fallback", t_scores

        top = scores.argsort()[::-1][:4]
        alternatives = [(faqs[i].id, round(float(scores[i]), 4)) for i in top
                        if faq is None or faqs[i].id != faq.id][:3]
        category = faq.category if faq else clf.predict(query)
        return RetrievalResult(
            faq_id=faq.id if faq else None,
            confidence=round(conf, 4),
            method=method,
            lang=lang,
            category=category,
            tfidf_score=round(t_score, 4),
            sbert_score=round(s_score, 4) if s_score is not None else None,
            elapsed_ms=(time.perf_counter() - start) * 1000,
            alternatives=alternatives,
        )
```

**Explanation.** This method is the core of the NLP pipeline (FR-01, FR-02, FR-03, FR-05). It detects the query language, computes TF-IDF cosine similarity against every active FAQ and accepts the best match directly when the score reaches the configurable threshold (0.75 by default). Otherwise the sentence-BERT model is used as the fallback stage: its semantic similarity is fused with the TF-IDF evidence (`fused = w·TF-IDF + (1−w)·SBERT`, w = 0.6) and the best FAQ is accepted if the fused score reaches the SBERT-stage threshold (0.35). If neither stage is confident the result is a fallback, and the category classifier still assigns one of the six categories so the query can be analysed by staff. The indexes are read under a lock and swapped atomically when they are rebuilt, so concurrent requests never see a half-built index. The method never generates text — it only returns the id of a verified FAQ, which is what keeps the chatbot free of hallucinations.

## 2. Arabic preprocessing — normalisation and light stemming

*Source: backend/nlp/preprocess.py — `normalize_arabic`, `stem_arabic`, `tokenize`*

```python
def normalize_arabic(text: str) -> str:
    """Orthographic normalisation of Arabic text."""
    text = ARABIC_DIACRITICS.sub("", text).replace(TATWEEL, "")
    return text.translate(_ALEF_MAP).translate(_ARABIC_DIGITS)


def _strip_ar_prefix(token: str) -> str:
    for p in _AR_PREFIXES:
        if token.startswith(p) and len(token) - len(p) >= 3:
            return token[len(p):]
    if token[:1] in ("و", "ب") and len(token) > 4:
        return token[1:]
    return token


def stem_arabic(token: str) -> str:
    """Light stemmer: strip one common prefix and one common suffix, keeping >= 3 letters."""
    token = _strip_ar_prefix(token)
    for s in _AR_SUFFIXES:
        if token.endswith(s) and len(token) - len(s) >= 3:
            token = token[: -len(s)]
            break
    return token


def tokenize(text: str, stem: bool = True, remove_stop: bool = True) -> list[str]:
    """Normalise and tokenise text into retrieval tokens (script-aware)."""
    out = []
    for tok in normalize_text(text).split():
        is_ar = bool(ARABIC_CHAR.match(tok))
        if is_ar:
            base = _strip_ar_prefix(tok)
            expanded = AR_SYNONYMS.get(tok, AR_SYNONYMS.get(base, tok)).split()
        else:
            expanded = EN_SYNONYMS.get(tok, tok).split()
        for t in expanded:
            if remove_stop and t in (AR_STOP if is_ar else EN_STOP):
                continue
            if stem:
                t = stem_arabic(t) if is_ar else _stemmer.stem(t)
            if t:
                out.append(t)
    return out
```

**Explanation.** Arabic words appear in many written forms: with or without diacritics, with different alef/hamza shapes, taa marbuta (ة) or haa (ه), and with attached prefixes such as the article "ال" or the conjunction "و". `normalize_arabic` removes diacritics and tatweel and unifies these letter variants; `stem_arabic` strips one common prefix and one common suffix while keeping at least three letters, so "الدراسة", "الدراسه" and "دراسي" all become the same stem. `tokenize` routes each token by script, so English tokens go through NLTK stop-word removal and Snowball stemming while Arabic tokens use the custom pipeline, and mixed queries ("رسوم IELTS") work. A small domain glossary maps abbreviations (GFP, HEAC, MoHERI) and Gulf colloquial words (جوال → هاتف) to the vocabulary of the knowledge base. CAMeL Tools was evaluated but not used because it requires older versions of libraries that sentence-transformers depends on (see the tuning log).

## 3. Chat endpoint — validation, retrieval, bilingual answer, logging

*Source: backend/routes/public.py — `POST /api/chat`*

```python
@public_bp.post("/chat")
@limiter.limit(lambda: current_app.config["CHAT_RATE_LIMIT"])
def chat():
    """Answer a student query with a verified FAQ or the fallback message; log it (FR-07)."""
    start = time.perf_counter()
    data = request.get_json(silent=True)
    if not isinstance(data, dict):
        return _bad_request("request body must be JSON")
    message = data.get("message")
    if not isinstance(message, str) or not message.strip():
        return _bad_request("'message' is required")
    message = message.strip()
    if len(message) > MAX_QUERY_LEN:
        return _bad_request(f"'message' must be at most {MAX_QUERY_LEN} characters")
    session_id = str(data.get("session_id") or uuid.uuid4().hex)[:64]

    result = get_engine().retrieve(message)
    lang = result.lang
    faq = db.session.get(FAQ, result.faq_id) if result.faq_id else None

    body = {
        "session_id": session_id,
        "query": message,
        "lang": lang,
        "method": result.method,
        "confidence": result.confidence,
        "category": result.category,
        "fallback": faq is None,
    }
    if faq:
        use_ar = lang == "ar" and bool(faq.answer_ar)
        body.update(
            faq_id=faq.id,
            question=faq.question_ar if lang == "ar" and faq.question_ar else faq.question_en,
            answer=faq.answer_ar if use_ar else faq.answer,
            answer_lang="ar" if use_ar else "en",
            answer_alt=faq.answer if use_ar else (faq.answer_ar or None),
            category=faq.category.name_en,
            category_ar=faq.category.name_ar,
        )
    else:
        contact = contact_details()
        body.update(
            faq_id=None,
            answer=FALLBACK_TEXT[lang].format(office=contact["office"]),
            answer_lang=lang,
            contact=contact,
        )
        cat = Category.query.filter_by(name_en=result.category).first() if result.category else None
        body["category_ar"] = cat.name_ar if cat else None
    # Near misses are offered as "Did you mean...?" suggestions
    alt_ids = [faq_id for faq_id, _score in result.alternatives]
    alts = {f.id: f for f in FAQ.query.filter(FAQ.id.in_(alt_ids), FAQ.is_active.is_(True)).all()} if alt_ids else {}
    body["suggestions"] = [_faq_brief(alts[i], lang) for i in alt_ids if i in alts][:3]

    elapsed = (time.perf_counter() - start) * 1000
    log = ConversationLog(session_id=session_id, query_text=message, detected_lang=lang,
                          matched_faq_id=result.faq_id, confidence=result.confidence, method=result.method,
                          category=body.get("category"), response_ms=elapsed)
    db.session.add(log)
    db.session.commit()
    body.update(log_id=log.id, response_ms=round(elapsed, 1))
    return jsonify(body)
```

**Explanation.** The public endpoint used by the widget. It is rate-limited per IP (NF-05), validates the JSON body (non-empty text, at most 500 characters) and calls the retrieval engine. When an FAQ is found the answer is returned in the language the student wrote in (the Arabic answer for Arabic queries, FR-01) together with the category and confidence; otherwise the fallback message is returned with the escalation contact details stored in the settings table (FR-05). Near misses are returned as "Did you mean…?" suggestions. Every query — answered or not — is written to `conversation_logs` with the session id, detected language, matched FAQ, confidence, method, category and measured response time (FR-07), which feeds the admin statistics and the unanswered-queries list.

## 4. FAQ management with automatic index rebuild

*Source: backend/routes/admin.py — `create_faq`, `toggle_faq`; backend/app/nlp_service.py — `bump_faq_version`, `get_engine`*

```python
@admin_bp.post("/faqs")
@login_required
def create_faq():
    data = json_body()
    if data is None:
        return error("request body must be JSON")
    clean, err = validate_faq(data)
    if err:
        return error(err)
    faq = FAQ(**clean)
    db.session.add(faq)
    db.session.commit()
    bump_faq_version()  # rebuild the retrieval index
    return jsonify(faq.to_dict()), 201


@admin_bp.patch("/faqs/<int:faq_id>/toggle")
@login_required
def toggle_faq(faq_id):
    faq = db.session.get(FAQ, faq_id)
    if not faq:
        return error("FAQ not found", 404)
    faq.is_active = not faq.is_active
    faq.updated_at = utcnow()
    db.session.commit()
    bump_faq_version()
    return jsonify(faq.to_dict())


def bump_faq_version() -> None:
    """Mark the knowledge base as changed; every worker rebuilds on its next query."""
    Setting.set("faq_version", int(Setting.get("faq_version", 0) or 0) + 1)
    db.session.commit()


def get_engine() -> HybridRetriever:
    """Return an up-to-date retriever, rebuilding it when FAQs or thresholds changed."""
    version, settings = _engine_settings()
    with _lock:
        engine = _state["engine"]
        if engine is None or _state["version"] != version:
            cfg = current_app.config
            engine = HybridRetriever(
                tfidf_threshold=settings["confidence_threshold"],
                sbert_threshold=settings["sbert_threshold"],
                fusion_weight=settings["fusion_weight"],
                use_sbert=cfg["ENABLE_SBERT"],
                sbert_model=cfg["SBERT_MODEL"],
            ).fit(_faq_docs())
            _state.update(engine=engine, version=version, settings=settings)
        elif _state["settings"] != settings:  # thresholds edited in admin - no rebuild needed
            engine.tfidf_threshold = settings["confidence_threshold"]
            engine.sbert_threshold = settings["sbert_threshold"]
            engine.fusion_weight = settings["fusion_weight"]
            _state["settings"] = settings
        return engine
```

**Explanation.** Staff manage FAQs through the dashboard without code (FR-06, NF-06). Every change — create, update, enable/disable, delete or CSV import — is protected by `@login_required` (NF-05), validated, saved, and then `bump_faq_version()` increments a version number stored in the database. Each API worker process keeps its own retrieval engine; on every chat request `get_engine()` compares its version with the database and rebuilds the TF-IDF index, the category classifier and the SBERT embeddings (cached on disk by content hash) when they differ. This keeps several gunicorn workers consistent without restarting the service, so a new FAQ is answerable on the very next question (screenshot 21). Threshold changes made in Settings are applied without a rebuild.

## 5. Embeddable widget — one script tag, isolated with Shadow DOM

*Source: frontend/widget/src/embed.jsx*

```jsx
/*
 * Embeddable entry point (FR-08). A college website adds the chatbot with one tag:
 *
 *   <script src="https://chatbot.example.edu.om/widget.js"
 *           data-api="https://chatbot.example.edu.om"   (optional - defaults to the script's origin)
 *           data-lang="en"                               (optional - en | ar)
 *           data-title="Gulf College Assistant"          (optional)
 *           data-open="false" defer></script>
 *
 * The widget renders inside a Shadow DOM so its styles are isolated from the host page.
 */
import { createRoot } from "react-dom/client";
import Widget from "./Widget.jsx";
import css from "./styles.css?inline";

// Captured while the script executes; document.currentScript is null inside later callbacks.
const SCRIPT = document.currentScript || document.querySelector('script[src*="widget.js"]');
const currentScript = () => SCRIPT;

function mount(options = {}) {
  const script = currentScript();
  const scriptOrigin = script?.src ? new URL(script.src, window.location.href).origin : window.location.origin;
  const cfg = {
    apiBase: options.api || script?.dataset.api || scriptOrigin,
    defaultLang: options.lang || script?.dataset.lang || (document.documentElement.lang === "ar" ? "ar" : "en"),
    title: options.title || script?.dataset.title,
    startOpen: (options.open ?? script?.dataset.open) === true || script?.dataset.open === "true",
  };
  const host = document.createElement("div");
  host.id = "college-faq-widget";
  document.body.appendChild(host);
  const shadow = host.attachShadow({ mode: "open" });
  const style = document.createElement("style");
  style.textContent = css;
  shadow.appendChild(style);
  const container = document.createElement("div");
  shadow.appendChild(container);
  createRoot(container).render(<Widget {...cfg} />);
  return host;
}

if (!SCRIPT || SCRIPT.dataset.autoMount !== "false") {
  if (document.readyState === "loading") document.addEventListener("DOMContentLoaded", () => mount());
  else mount();
}

export { mount };
```

Embedding on any college page (FR-08):

```html
<script src="https://chatbot.college.edu.om/widget.js"
        data-title="Gulf College Assistant" data-lang="en" defer></script>
```

**Explanation.** The widget is built by Vite in library mode into one self-contained `widget.js` file (React, Axios and CSS included). When a college website loads it, the script reads optional `data-*` attributes from its own `<script>` tag (API address, default language, title), creates a host element, attaches a Shadow DOM and renders the React chat widget inside it with its stylesheet. The Shadow DOM isolates the widget completely: the college's CSS cannot break the chat, and the chat's CSS cannot change the college page. By default the API address is the origin the script was loaded from, so the only integration needed is the single `<script>` tag — demonstrated by `docs/demo-college-site.html` (screenshot 01) and test cases TC24–TC25.
